# 口播剪辑方法：先参考、再编排、后实现

2026-10-07，用户明确将柱子哥农场参考片的剪辑模式用于以后所有 `talking-head` 视频。直接在现有口播流程中执行，不建立“农场口播包”、风格选择或新的中间层。本决定不改变产品宣传和知识讲解流程。

## 所有口播的默认剪辑模式

视觉依据是 [农场参考原片](/Users/winter/Desktop/抖音无水印视频/柱子哥TzFilm/SaveTik.co_7665543600142404864-hd.mp4)，已观察的画面、连续动作和时间区段见 [参考拆解](/Users/winter/Movies/WinterVideoAgentProjects/reference-7665543600142404864/analysis/farm-style-2026-10-06/农场参考片-画面与动效拆解.md)。拆解是观察记录；准确字体、缓动曲线和用于本期原片的布局参数仍需核定，不把估计值当作作者实现。

- **画面组织**：人物保持原构图，章节标记、主标题或大数字、解释信息、证据画面、字幕形成清晰层级。信息成组对齐，注解依附主体，真实照片或界面有足够尺寸供阅读。
- **信息展开**：按口播逐项建立，同一段已出现的相关信息可以累积保留；换主题时成组交接。人物已经足以表达的段落保留纯口播，不要求每句都加效果。
- **动作表达**：数字从起值增长到结果，比较条按共同尺度伸展，照片和证据带位移进入，节点随关系激活，结论可以通过缩放与落位强调。动作要表达内容，包含建立、变化、阅读和收束；不以文字弹出、漂浮素材或持续晃动代替。
- **排版与颜色**：沿用参考中的粗体主次关系和语义配色。绿色用于积极结果、规模等信息，蓝色或青色用于技术关系，黄色用于时间、比例与重点，红色用于否定或风险；灰色用于次要说明。角色按内容选择，不将所有元素统一染绿。浅背景上的文字改用清晰的深色实心字，不添加粗糙白边。
- **原片约束**：默认保留完整 4:3 口播，不裁切、不缩小原片预留空区，元素直接出现在原画面上。禁止添加覆层遮罩、无关装饰线和白色文字描边；参考中的暗色底板不能成为绕过无遮罩要求的理由。按人物和字幕调整布局，不照搬参考的 16:9 坐标。

每期变化的是文案、对象、真实素材、数据和时序，以及适配原构图所需的位置与尺寸。整体剪辑模式保持一致，不重新发明视觉方向；不复制参考的农场事实、人物身份或作者署名。上游卡片与成熟代码用于实现该模式，不能因某张卡容易调用就改变目标画面。

参考复建及4:3新原片适配已形成 [可用里程碑 v1](milestone-talking-head-reference-v1.md)。先沿用其中的动作实现和相关已认可产物，按本期内容填写原生配置；只在表达能力确实不足时补代码。本文负责制作判断，既有入口负责执行；方法维护本身不要求额外制作一条测试视频，后续实现和渲染沿用用户的任务与授权。

## 先完成什么，再写代码

新视频或需要重新编排的区段，按「理解口播与原片 → 从农场参考选择对应表达 → 检索成熟实现 → 说明逐镜动作 → 实现」推进。施工说明写入已有项目记录，不增加新的审批或中间层。单期续作只补受影响部分的依据，沿用已经确认的设计。单纯修正错字、时序或素材路径无需重新设计。

### 1. 从内容和原片确定画面任务

按语义段整理时间、口播内容、观众需要理解的事、现有证据和实际画面。语义段可以跨几句话，不按每句结束机械换效果。

先判断这一段是在介绍对象、比较、解释步骤、展示证据、描述关系、补充条件还是收束观点。再判断它是否需要补充画面；人物本身能充分表达时，可以保持口播。检查实际背景明暗、人物动作和原字幕，画幅、保护区和字体对比按本期原片确定。

### 2. 检索并分析能解决同一任务的参考

农场参考片是固定视觉依据，先定位能表达本期任务的段落，再从 [成品视觉参考](../skills/winter-video-agent/references/visual-sources.md) 和 [案例库](visual-case-library.md) 找能实现对应动作的成熟代码或素材。其他作品用于补充实现与表达细节，不重新选择本期整体风格。学习对象、信息关系和动作过程，不能仅凭主题、封面或效果名称决定套用。

选中的参考写清以下内容，保存在外部项目的参考分析或分镜里：

| 记录 | 要回答的问题 |
| --- | --- |
| 具体出处 | 哪个作品、哪个时间段或哪些连续帧？卡片和准确实现在哪里？上游提交是什么？ |
| 画面任务 | 这段让观众理解了什么，与本期哪一段的问题相近？ |
| 信息组织 | 谁是主体，哪些信息归为一组，证据与注解如何依附主体？ |
| 动作过程 | 对象怎样建立、展开或改变，哪里停下来供阅读，如何收束或交接？ |
| 适配决定 | 本期借用哪些方法？根据人物、背景、素材、时长需要改哪些部分？ |

有动态样片时查看动作过程；只有静帧或源码时，明确实际看到了什么，未验证的动态效果仍是候选。无需遍历整个图库，也不为一段普通修订重复搜索。检索结果必须进入编排理由，不能只列出几个仓库名就开始画图。

### 3. 写逐镜施工单，形成完整画面过程

在代码或渲染计划之前，先用自然语言说明这一镜。施工单至少包括：

| 字段 | 内容 |
| --- | --- |
| 时间与口播 | 原片区间、对应内容、时序依据及精度 |
| 观众要理解什么 | 本镜承担的解释任务和重点 |
| 参考依据 | 参考区段、选中卡片/实现、借用方法与本期适配理由 |
| 对象与证据 | 主体、辅助对象、真实素材或明确标注的示意、素材缺口 |
| 动作过程 | 建立对象 → 展开信息或表达变化 → 停留阅读 → 收束或交接；有意静止的镜头写明原因 |
| 布局与可读性 | 本期人物/字幕保护区、主次尺寸、按实际背景选择的文字对比 |
| 前后衔接 | 上一镜留下什么，这一镜改变什么，下一镜接什么 |
| 落地方式 | 已接通配方、待适配的成熟代码或确需补充的实现 |

为全片每个语义段标明处理方式，包括主动保留口播的段落。少数代表镜头得到认可后，把相同的编排判断用于其余区段；不能只完成样片段落，其他需要解释的段落继续沿用旧式文字弹出。

### 4. 按设计选择实现

先检查现有配方和相应上游准确实现是否能表达施工单。成熟代码可按 [代码吸收规则](reuse-plan.md) 复用，记录仓库、提交和原始路径，在自有目录适配；不在子模块中修改、安装依赖或渲染。只有明确缺少表达能力时才补充实现。

数据计划负责本期素材、位置、时序与文字；代码负责执行这些决定。不能先随意写一套动画，再用成品倒推设计理由。生成式物体、插画优先使用可用的 AI 生图工具；真实界面、操作和数据来自本期真实素材。

## 编排时怎样作判断

| 内容关系 | 可借用的方法 | 使用前提 |
| --- | --- | --- |
| 数量或规模比较 | 数字增长、共同尺度的比较条、结果强调 | 数字与单位有依据，动画帮助理解规模；不虚构进度或比例 |
| 对象或内容从 A 到 B | 建立两端，同一对象移动、重排或进入目标，再接证据 | 区分流程示意与真实操作结果 |
| 多项并列信息 | 成组展开、共用对齐、依次聚焦或收拢 | 不把并列清单画成必须依次完成的步骤 |
| 有先后条件的步骤 | 状态推进、节点激活、条件分支 | 动作顺序与口播中的步骤和条件一致 |
| 界面或操作证据 | 真实页面成为主角、局部放大、说明随对应位置出现 | 保证关键内容可读；没有真实证据时不生成伪界面冒充 |
| 观点或收束 | 让人物、简洁结论或前述对象的归纳承担重点 | 根据语气决定动作量，不强行加入图表或装饰 |

这张表用于在农场参考片的剪辑模式内选择对应表达，不要求每段使用同一个效果。画面的丰满来自足够大的主体、明确的信息层级、关系展开、真实证据和合适的阅读时间。无关线条、漂浮标签、重复卡片与一直晃动不能替代这些组织工作。

排版层级、语义配色和动作节奏沿用默认模式；文字明暗、位置与尺寸根据原片背景和构图适配。保持原画幅和无遮罩约束，不以降低可读性换取表面上相同的颜色，也不将适配变成重新自由设计。

## 预览与反馈如何影响下一步

用户要求制作预览时，选能代表本期主要编排问题的片段，按施工单做出可看的结果。参考分析或规则调整本身不触发新样片。检查口播与动作是否对应、证据是否可读、人物字幕是否受影响，以及实际需要的产物完整性。发现明确故障只修相关部分，不进行没有具体问题的反复审美重渲或回归。

审阅要落实到具体区间和判断：对象是否清楚、动作是否表达内容、信息是否形成结构、衔接是否成立。预览生成成功不等于审美通过，某一段通过也不代表全片通过。沿用用户已有授权；不额外要求逐张施工单批准，用户要求先看结果时先提供代表片段。

反馈先记入本期决定。用户在 2026-10-07 明确确认的农场剪辑模式已经是全局口播规则；其他反馈只有用户明确要求才升级。具体素材、数据和本期位置、时序参数仍留在单期项目。
