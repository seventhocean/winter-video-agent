# 口播剪辑方法：先参考、再编排、后实现

2026-10-06，用户明确要求把本次剪辑的制作逻辑作为口播基准。基准是如何分析、选择和编排；每期的配色、元素、版式和具体动效仍由内容、原片与用户要求决定。本方法用于 `talking-head`，不是三条流程共用的视觉模板。

## 先完成什么，再写代码

新视频或需要重新设计的区段，按「理解口播与原片 → 分析用户案例和素材库 → 形成逐镜施工单 → 选择实现 → 出代表片段」推进。单期续作只补受影响部分的依据，沿用已经确认的设计。单纯修正错字、时序或素材路径无需重新设计。

### 1. 从内容和原片确定画面任务

按语义段整理时间、口播内容、观众需要理解的事、现有证据和实际画面。语义段可以跨几句话，不按每句结束机械换效果。

先判断这一段是在介绍对象、比较、解释步骤、展示证据、描述关系、补充条件还是收束观点。再判断它是否需要补充画面；人物本身能充分表达时，可以保持口播。检查实际背景明暗、人物动作和原字幕，画幅、保护区和字体对比按本期原片确定。

### 2. 检索并分析能解决同一任务的参考

用户提供的案例优先分析，再从 [成品视觉参考](../skills/winter-video-agent/references/visual-sources.md) 和 [案例库](visual-case-library.md) 找相近的表达方法。学习对象、信息关系和动作过程，不能仅凭主题、封面或效果名称决定套用。

选中的参考写清以下内容，保存在外部项目的参考分析或分镜里：

| 记录 | 要回答的问题 |
| --- | --- |
| 具体出处 | 哪个作品、哪个时间段或哪些连续帧？卡片和准确实现在哪里？上游提交是什么？ |
| 画面任务 | 这段让观众理解了什么，与本期哪一段的问题相近？ |
| 信息组织 | 谁是主体，哪些信息归为一组，证据与注解如何依附主体？ |
| 动作过程 | 对象怎样建立、展开或改变，哪里停下来供阅读，如何收束或交接？ |
| 适配决定 | 本期借用哪些方法？根据人物、背景、素材、时长需要改哪些部分？ |

有动态样片时查看动作过程；只有静帧或源码时，明确实际看到了什么，未验证的动态效果仍是候选。无需遍历整个图库，也不为一段普通修订重复搜索。检索结果必须进入编排理由，不能只列出几个仓库名就开始画图。

### 3. 写逐镜施工单，形成完整画面过程

在代码或渲染计划之前，先用自然语言说明这一镜。施工单至少包括：

| 字段 | 内容 |
| --- | --- |
| 时间与口播 | 原片区间、对应内容、时序依据及精度 |
| 观众要理解什么 | 本镜承担的解释任务和重点 |
| 参考依据 | 参考区段、选中卡片/实现、借用方法与本期适配理由 |
| 对象与证据 | 主体、辅助对象、真实素材或明确标注的示意、素材缺口 |
| 动作过程 | 建立对象 → 展开信息或表达变化 → 停留阅读 → 收束或交接；有意静止的镜头写明原因 |
| 布局与可读性 | 本期人物/字幕保护区、主次尺寸、按实际背景选择的文字对比 |
| 前后衔接 | 上一镜留下什么，这一镜改变什么，下一镜接什么 |
| 落地方式 | 已接通配方、待适配的成熟代码或确需补充的实现 |

为全片每个语义段标明处理方式，包括主动保留口播的段落。少数代表镜头得到认可后，把相同的编排判断用于其余区段；不能只完成样片段落，其他需要解释的段落继续沿用旧式文字弹出。

### 4. 按设计选择实现

先检查现有配方和相应上游准确实现是否能表达施工单。成熟代码可按 [代码吸收规则](reuse-plan.md) 复用，记录仓库、提交和原始路径，在自有目录适配；不在子模块中修改、安装依赖或渲染。只有明确缺少表达能力时才补充实现。

数据计划负责本期素材、位置、时序与文字；代码负责执行这些决定。不能先随意写一套动画，再用成品倒推设计理由。生成式物体、插画优先使用可用的 AI 生图工具；真实界面、操作和数据来自本期真实素材。

## 编排时怎样作判断

| 内容关系 | 可借用的方法 | 使用前提 |
| --- | --- | --- |
| 数量或规模比较 | 数字增长、共同尺度的比较条、结果强调 | 数字与单位有依据，动画帮助理解规模；不虚构进度或比例 |
| 对象或内容从 A 到 B | 建立两端，同一对象移动、重排或进入目标，再接证据 | 区分流程示意与真实操作结果 |
| 多项并列信息 | 成组展开、共用对齐、依次聚焦或收拢 | 不把并列清单画成必须依次完成的步骤 |
| 有先后条件的步骤 | 状态推进、节点激活、条件分支 | 动作顺序与口播中的步骤和条件一致 |
| 界面或操作证据 | 真实页面成为主角、局部放大、说明随对应位置出现 | 保证关键内容可读；没有真实证据时不生成伪界面冒充 |
| 观点或收束 | 让人物、简洁结论或前述对象的归纳承担重点 | 根据语气决定动作量，不强行加入图表或装饰 |

这张表用于选择表达方法，不规定每次都使用同一种效果。画面的丰满来自足够大的主体、明确的信息层级、关系展开、真实证据和合适的阅读时间。无关线条、漂浮标签、重复卡片与一直晃动不能替代这些组织工作。

颜色、字重、描边、是否使用底板、是否保留人物及画幅由本期要求和画面决定。某一期浅背景上的深色实心字，不能成为另一支深背景视频的默认答案。

## 预览与反馈如何影响下一步

选能代表本期主要编排问题的片段，按施工单做出可看的结果。检查口播与动作是否对应、证据是否可读、人物字幕是否受影响，以及实际需要的产物完整性。发现明确故障只修相关部分，不进行没有具体问题的反复审美重渲或回归。

审阅要落实到具体区间和判断：对象是否清楚、动作是否表达内容、信息是否形成结构、衔接是否成立。预览生成成功不等于审美通过，某一段通过也不代表全片通过。沿用用户已有授权；不额外要求逐张施工单批准，用户要求先看结果时先提供代表片段。

反馈先记入本期决定。只有用户明确要求，才将可迁移的方法升级为 Agent 规则；具体元素或视觉参数仍留在单期项目。

## 本次交付作为方法案例

外部项目 `2026-10-05-ai-phone-migration` 的「AI 帮我换手机」完整成片已获用户确认。其计划、素材、预览和交付保持在仓库外，查该项目的 `project.json` 与 `decisions/`；不将视频复制成仓库模板。

| 本次经历 | 可迁移的制作判断 |
| --- | --- |
| 早期画面主要是文字与素材出现，用户认为与参考差距大 | 搜索之后必须分析参考的信息组织和动作过程，并落实到施工单 |
| 应用从旧设备展开，形成集合，再进入新设备；随后接真实界面 | 用对象的变化表达口播内容，把示意与证据组织为连续过程；设备、图标与布局按下一期内容重选 |
| 最初只有约 47–65 秒真正重新编排，其余区段仍旧 | 代表片段是验证编排方法；后续要逐段应用判断，并覆盖需要解释的全部区间 |
| 最后调整文字边缘、对比、冗余线条与主体大小 | 在当前背景和素材上做针对性细化，丰满靠主次与对象关系；不把本期字体参数固化 |
