# 三条视频流程契约

## 设计原则

Winter Video Agent 只有一个入口，但内部维护三条独立流程。入口负责判断任务类型、创建项目、展示状态和调用对应 workflow。workflow 对最终成片负责。

每个项目只有一条 `primary_workflow`：

- `talking-head`
- `product-promo`
- `knowledge-explainer`

一条流程可以调用其他资产。例如口播片可以使用 ShotCraft 的产品卡，也可以使用 ThreeUI 的 shader；这不会改变项目的主流程。

## 公共生命周期

三条流程都对外报告以下状态：

| 状态 | 含义 |
| --- | --- |
| `draft` | 已创建项目，输入仍可补充 |
| `inspected` | 已读取素材、文稿和目标，已发现缺失项 |
| `prepared` | 运行环境、素材登记和前置处理完成 |
| `planned` | 当前流程的分镜或制作计划已形成 |
| `previewed` | 已生成可供判断方向的最小预览 |
| `production` | 已进入全量制作 |
| `qa` | 正在执行成片与流程专属检查 |
| `delivered` | 已保存正式交付文件与校验信息 |
| `blocked` | 缺少必需输入或外部条件，并记录具体原因 |

状态只统一进度，不规定内部文件结构。每条流程可以有自己的子阶段。

## 公共操作

| 操作 | 责任 |
| --- | --- |
| `new` | 创建外部项目目录，写入项目身份和主流程 |
| `inspect` | 读取文稿、媒体信息、目标平台和已有决定 |
| `prepare` | 检查工具，登记素材，完成可重复的前置处理 |
| `preview` | 生成最小但足以判断方向的样片或关键帧 |
| `render` | 按流程构建正式视频或指定区段 |
| `qa` | 执行公共媒体检查与流程专属检查 |
| `deliver` | 复制确认产物，写入媒体参数和哈希 |
| `clean` | 清理明确可重建的临时文件与缓存引用 |

所有操作应支持机器可读结果，至少包含项目、流程、状态、产物、警告和下一步。

## 公共项目记录

未来的 `project.json` 至少表达：

~~~json
{
  \"project_id\": \"2026-09-12-example\",
  \"primary_workflow\": \"talking-head\",
  \"status\": \"draft\",
  \"format\": {
    \"width\": 1080,
    \"height\": 1920,
    \"fps\": 30
  },
  \"inputs\": [],
  \"decisions\": [],
  \"artifacts\": [],
  \"runtime\": {},
  \"provenance\": []
}
~~~

这只是公共外壳。SHOTBOOK、产品 shot manifest 和讲解 storyboard 继续使用各自格式，不嵌进一个万能 timeline。

## 素材契约

每份素材登记：

- 稳定 ID 和用途。
- 原始绝对路径或受控存储引用。
- 大小、哈希、媒体类型、时长、分辨率、帧率和音轨。
- 是否允许复制、代理、裁切或生成衍生文件。
- 来源和隐私备注。
- 被哪些镜头或阶段使用。

文件分为四类：

1. 外部原始素材：默认不复制、不删除。
2. 项目拥有的小型输入与决定：长期保留。
3. 可重建的代理、时间戳、预览和渲染缓存：允许清理。
4. 正式交付：保留版本、媒体参数和哈希。

## Workflow A：talking-head

### 适用任务

- 已有真人口播视频，需要剪辑、字幕、B-roll、图片、录屏、特效或转场。
- 已有文稿和最终配音，需要做内容驱动的口播成片。
- 修改已有口播项目中的某个镜头或区段。

### 必需输入

- 最终人声或包含最终人声的视频。
- 文稿；若没有，可从音频转写后由用户确认。
- 目标画幅、时长范围和发布平台。

### 可选输入

- 真人原片、补充素材、证据截图、品牌规则、参考片和既有字幕。

### 内部阶段

1. 探测媒体并确认最终音频。
2. 生成或校正 CPU 字级时间戳。
3. 标记句子、关键词和节拍锚点。
4. 创建 SHOTBOOK：每镜的语义目的、卡片、素材、画面层、字幕、音效和转场。
5. 做代表镜或短区段预览。
6. 锁定方向后逐段制作。
7. 分段渲染、缓存和合成。
8. 执行节拍、静止、卡片一致性、音效和公共媒体 QA。

### 主要产物

- transcription/timestamps。
- SHOTBOOK。
- 镜头源码与素材映射。
- 分段预览和正式分段。
- 合成成片、QA 报告和交付记录。

### 首批代码来源

TalkCraft 的 `timestamps_cpu.py`、SHOTBOOK lint、preflight、`render_shots.mjs`、`render_stills.mjs`、freeze/motion/beat/SFX 检查，以及一个经过验证的镜头卡。

## Workflow B：product-promo

### 适用任务

- App、网站、软件、硬件或服务的产品宣传片。
- 产品功能演示、版本发布、广告短片或功能镜头。
- 需要从真实页面、产品素材和卖点建立商业镜头。

### 必需输入

- 产品名称与可访问的产品资料。
- 受众、目标行为、核心卖点和发布场景。
- 画幅、时长范围和品牌约束。

### 可选输入

- 网站 URL、Figma、录屏、产品截图、Logo、品牌字体、实拍素材和参考广告。

### 内部阶段

1. 理解产品、用户和购买动机。
2. 提出视觉方向并生成 styleframe。
3. 用户或既有品牌规则确认方向。
4. 将每个核心卖点映射为镜头。
5. 捕获真实页面、透明裁切和布局信息。
6. 建立 shot manifest，逐镜实现。
7. 设计转场、字幕、覆盖层、音乐和音效。
8. 生成短样片或关键镜预览。
9. 正式渲染并执行产品可读性、品牌、声音和公共媒体 QA。

### 制作模式

- 模板模式：复用已验证的视觉体系和镜头组合。
- 自主模式：Agent 根据 brief 独立提出镜头语言。
- 共创模式：在 styleframe 和 storyboard 节点与用户共同选择。

### 主要产物

- product brief。
- visual direction 与 styleframe。
- feature-to-shot mapping。
- 页面捕获、裁切素材和 layout。
- shot manifest、镜头源码、音频设计。
- 成片、QA 报告和交付记录。

### 首批代码来源

ShotCraft 的 pipeline、PageCam、页面捕获方法、camera/motion helper，以及一个与真实项目匹配的产品镜头卡。

## Workflow C：knowledge-explainer

### 适用任务

- 从主题、文章或现有文稿生成知识讲解视频。
- 需要研究、旁白、TTS、字幕、章节和图形解释的成片。
- 没有真人素材，以代码动画、图形和生成素材为主体。

### 必需输入

- 主题、文章或待确认文稿。
- 语言、目标受众、画幅和时长范围。
- 是否允许联网研究及事实来源要求。

### 可选输入

- 指定声音、视觉 profile、参考资料、品牌规则、图片或视频素材。

### 内部阶段

1. 研究并登记事实来源。
2. 建立解释结构与章节。
3. 完成旁白并确认。
4. 生成 TTS、句级和词级时间轴。
5. 每句建立 storyboard token 和视觉变化。
6. 配置 overlay、标题、字幕、章节、HUD 和 credits。
7. 先渲染前 30 秒或一个完整章节。
8. 按动态分组完成全片。
9. 执行静态自检、帧指标、运动、字幕、事实来源和公共媒体 QA。

### 视觉 profile

Anything2Explainer 的黑底、白线、紫色强调、星点或点阵背景是第一个 `profile`。知识讲解 workflow 本身不锁定该风格，后续 profile 仍需遵守相同的研究、旁白、storyboard、预览和 QA 契约。

### 主要产物

- research notes 与来源清单。
- 已确认旁白、TTS 和时间轴。
- 章节与句级 storyboard。
- profile 配置与分组 composition。
- 预览、成片、QA 报告和交付记录。

### 首批代码来源

Anything2Explainer 的 `tts_build.py`、`render_storyboard.py`、动态化后的分组预览、`selfcheck.py`、`frame_metrics.py`、`motion_check.py` 和一个完整黄金示例。

## 资产库契约

资产库不能自行成为 workflow。每个纳入的资产至少记录：

- 名称、类别和可搜索描述。
- 来源仓库、提交和路径。
- 支持的画幅、颜色、主题和 workflow。
- 输入参数、字体、媒体和运行依赖。
- 是否已通过确定性、seek-safe、静帧和正式渲染检查。
- 缩略图或短预览。

TalkCraft 与 ShotCraft 的卡片保留各自语义；ThreeUI 组件在通过帧驱动适配后才进入可用状态。

## 修改与续作

用户提出修改时，Agent 先读取原项目记录：

1. 保持原 `primary_workflow`。
2. 找出受影响的决定、素材、镜头和分段。
3. 生成局部预览。
4. 只失效相关缓存和产物。
5. 重新执行受影响 QA，并保留新旧版本关系。

项目反馈默认只对该项目生效。需要沉淀为全局规则时，必须由用户明确提出。

## 公共 QA

所有 workflow 至少检查：

- 输出文件存在且可被 ffprobe 读取。
- 分辨率、帧率、时长和音轨符合项目配置。
- 无异常黑帧、空白区段、缺失素材或解码错误。
- 画面和音频时长误差在阈值内。
- 字幕与安全区不越界。
- 交付文件记录大小、媒体参数和 SHA-256。

流程专属 QA 由对应 workflow 增加。独立复核可以在执行环境允许时启用，但不是流程正确性的前提。
