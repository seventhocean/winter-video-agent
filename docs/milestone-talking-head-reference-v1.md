## 已有实现怎样选择

| 内容任务 | 现有实现 | 沿用的动作逻辑 |
| --- | --- | --- |
| 人物或对象介绍 | `identity-stack` | 主体先建立，相关事实依次累积，行动信息依附主体 |
| 数量与规模比较 | `metric-comparison` | 数字增长，横条共用尺度，结果在比较完成后出现 |
| 计数后解释处理步骤 | `metric-process` | 主数字与真实来源先建立，三个步骤依次累积，结果进入最后一步 |
| 并列对象逐项说明 | `grid-to-hero.focusIndices` | 集合建立，当前项放大、其他项保留，归位后继续下一项 |
| 界面或图片证据 | `evidence-image` | 单一主证据落位，章节和说明随证据呈现，保持可读尺寸 |
| 投入、步骤和日期跨度 | `development-time` | 大结论、三步流程和双日期线顺序建立；日期差由数据计算 |
| 分类与中心关联 | `database-relations` | 中心和分类建立，关系统一激活，再出现结论 |
| 数值跨越条件并触发结果 | `temperature-alert` | 同一读数驱动条形揭示与超限颜色，再接风险和处理方式 |
| 观点收束 | `verdict-stamp` | 观点先建立，再短促缩放落位，保持阅读 |

这张表是现有代码的使用索引，不是自动导演程序。选用时仍需确认本期语义、素材和可用空间；不能把所有步骤都限制为三项，或将不同任务硬塞进已有场景。其余两张原生 TalkCraft 卡也继续保留，只有能表达目标画面时才选用。参数见 [原生执行说明](../skills/winter-video-agent/references/native-talkcraft.md)。

## 下一期直接执行的顺序

1. 读取本文件、口播剪辑方法及本期 `project.json/decisions/`。确认主流程、原片、原声和用户要求；单期文件放在仓库外。
2. 按语义段理解全片，检查人物动作、字幕和实际背景。注明时间锚点精度，手工定位不称为字级对齐。
3. 对需要解释的区段，从上述已实现表达和农场参考中找到对应过程；查看相关成品或已认可基准，再查准确实现。纯口播段也记录保留理由。
4. 在本期已有 `decisions/` 写逐镜施工：主体、证据、建立、变化、阅读、收束及前后衔接。然后填写原生 SHOTBOOK。优先更换素材、文字、数据、时间和放置参数，沿用动作代码；只在确实缺少表达能力时补组件。
5. 用现有 `prepare/preview/render --engine talkcraft-native` 执行。根据本期背景选择深浅文字，保护人物和字幕，保持完整原画幅。Studio 是 Remotion 预览工具；它的地址或端口不作为基线版本。
6. 按已有授权提供预览或成片。记录实际故障并只修相关部分；用户要求先看结果时先交付结果，不自动多轮审美重渲。局部认可保持局部范围，全片制作须覆盖需要解释的全部区段。

保留完整 4:3 原片、不裁切人物、不缩小底片预留空区、无覆层遮罩、无无关装饰线、无白色文字描边，是当前口播的约束。真实截图自身的 UI 背景保留；AI 插画不能冒充真实操作证据。

## 后续维护与验证边界

今后在此基线上扩展。只换本期内容不重写公共动效；修复公共组件时沿用既有来源记录，按变更选择对应基准检查。修改数字计算就看计数/比较，修改重排就看应用集合，修改证据呈现就看主证据。没有相关代码变化时不重渲全部基准。

Git 标签固定代码和规则版本，外部清单固定实际产物。需要取回这一版本时从标签建立独立分支或查阅历史文件，保留当前工作，不用重置覆盖它。依赖、素材、预览和运行实例继续放在仓库外；清理时保留已认可产物、计划、施工、反馈与源码快照。
